# コード品質改善バックログ

作成日: 2026-10-15

## 目的と進め方

コード品質レビューで確認した改善候補を、小さな単位で順番に実施する。
通常時の打刻・休暇・期限・起床予約の挙動を維持し、異常時の挙動や受理する入力を変える項目は、その変更を記録する。

1. 対象項目の設計と受け入れ基準を確定する。
2. 必要な回帰テストを先に追加し、問題を再現する。
3. 対象範囲だけを改修する。
4. 対象テスト・全体テスト・関連する検証を実行し、全差分を確認する。
5. 本書に結果を記録してから次の項目へ進む。

実APIへの打刻・通知送信や実際のlaunchd・pmset操作は検証に使わない。
コミット・push・PR作成は、個別のユーザー指示に従う。

## 総合所見

Ruby・ThorのCLIと常駐Daemonを中心に、時刻計算を副作用のないDayPlannerへ分けた構成は維持する。
HTTP・通知・起床予約などの境界には依存注入と既存テストがあり、大きな設計変更を要する根拠は確認していない。
今回の主な改善領域は、トークン保存失敗からの回復、入力の型検証、運用スクリプトの回帰検出、操作案内と対応環境の整合である。

## Q01: トークン保存失敗後の保存再試行

- 対象: `lib/ak4_punch/token_store.rb`、CLI・Daemonの呼び出し箇所、関連spec。
- 問題: API再発行後に保存が失敗すると、メモリ上のトークン・期限だけが更新される。次tickでは更新不要と判断し、保存を再試行しない。
- 方針: 新トークンは保持し、未完了の保存を再試行する。保存のためだけにAPI再発行を繰り返さない。
- 受け入れ基準: 保存失敗中は再試行対象となり、復旧後に同じトークンを保存・再読込できる。保存再試行は既存の打刻実行機会に載せ、打刻の期限・リトライ窓は延長しない。期限切れ・全休などで打刻経路に入らない間は保存待ちを保持する。
- 必要な検証: 保存失敗→再失敗→復旧→再読込、API呼び出し回数、再発行API自体の失敗、Daemonからの再試行。
- 挙動変更: 保存失敗後に、従来行われなかった保存再試行を行う。
- 実施結果: TokenStore内部に保存待ち状態を追加し、保存成功後だけ解消する。CLI・Daemonのログと通知は更新・保存に適う説明へ揃えた。保存データ形式・atomic write・0600・fsync・通知の同日抑制を維持した。
- 検証: 回帰テスト6例を追加。修正前は対象137例中5件失敗し、修正後は対象141例・全体397例が成功。メインでもTokenStore・Daemonの137例成功と全差分を確認。`git diff --check`成功。

## Q02: トークン保存データの読み込み契約と明示エラー

- 対象: `lib/ak4_punch/token_store.rb`、同spec、READMEの復旧案内。
- 問題: JSON構文不正・I/O例外はシードへ退避する一方、配列・null・数値トークンなどは型例外で起動を停止する。
- 方針: ファイルの読み込みがENOENTならシードから開始する。他のI/O失敗・JSON構文不正・保存構造不正は `TokenStore::Error` とする。ルートはオブジェクト、tokenは空でない文字列を要求し、tokenの正規化はしない。expired_atはnil・欠落・文字列を許可し、解析不能な文字列は従来どおり期限不明として再発行する。
- 受け入れ基準: 正常な保存データと初回セットアップを維持し、不正データ・読み込み失敗を区別できる。エラーにトークンや保存内容を出さない。
- 必要な検証: 正常・未作成・構文不正・ルート型不正・フィールド型不正・I/O失敗・機密値を出さないエラー。
- 挙動変更: 一部の読み込み失敗で、古いシードへの自動退避をやめて明示的に停止する。
- 実施結果: ENOENT以外の読取失敗と不正な保存データを明示エラーへ揃えた。期限不明・token文字列の非正規化・未知キー無視を維持し、例外のcauseからも保存内容が漏れないようにした。READMEに復旧方法を記載した。
- 検証: 先行8例追加後の旧実装は対象19例中5件失敗。修正後は関連149例・全体405例が成功。メインが全差分と検証ログを確認。`git diff --check`成功。

## Q03: 設定の構造・真偽値の検証

- 対象: `lib/ak4_punch/config.rb`、同spec、設定例またはREADMEの必要な説明。
- 問題: 引用した文字列 `"false"` が有効扱いになる。ルート・設定セクションの型不正も分かりやすい設定エラーにならない。
- 方針: ルート・各セクションはHashを要求し、nilは空設定として扱う。対象の真偽設定5項目はtrue・false・nilを許可し、明示nilはそのまま保持する。既定値、数値の丸め・フォールバックなどは必要なく変更しない。
- 受け入れ基準: 正常なYAML設定を維持し、紛れ込んだ文字列や数値を `Config::Error` で拒否する。エラーは項目名を示し、設定全体を表示しない。
- 必要な検証: 各真偽設定のtrue・false・nil・未指定、引用false、数値、ルート・セクション型不正、既存設定の回帰。
- 挙動変更: 誤って有効扱いしていた不正な設定値を起動時に拒否する。
- 実施結果: ルート・6セクション・5真偽設定の入口検証を追加。YAMLのfalseを空設定に潰さず、項目名を示す設定エラーとした。true・false・明示nil・既定値、Date許可、既存の数値・時刻・URL処理、入力dataの非破壊を維持した。
- 検証: 先行8例追加後の旧実装はConfig64例中6件失敗。修正後は関連224例・全体413例が成功。メインが全差分と検証ログを確認。`git diff --check`成功。

- 挙動変更: 更新終了したRuby系列での実行を受け付けない。
